# interfaces/

三台機器之間的**介面合約**。這是 monorepo 存在的主要理由：改介面時，各方的程式在同一個 commit 一起改。

## 規則

1. 介面變更必須在同一個 commit（或同一個 PR）內同步修改所有使用端。
2. 每個 schema 都有版本號；不相容的變更要升版號，並保留讀取舊版的能力或寫明遷移方式。
3. 所有跨機器訊息都帶**來源機器的時間戳**與**座標系名稱**。三台機器時鐘要同步（chrony），否則時間戳沒有意義。
4. 延遲預算寫在這裡，不要只存在腦中。

## 預計內容

| 目錄 | 內容 |
|---|---|
| `schemas/` | JSON schema（例如 roomscan 的 report schema 2） |
| `ros2_msgs/`（之後） | 自訂 ROS 2 msg/srv，發行版依 ADR 0003 |
| `frames.md`（之後） | 座標系定義：map、odom、base_link、cam_left… |
| `latency_budget.md`（之後） | 各鏈路的延遲上限與逾時行為 |

SLAM 關鍵幀的資料結構不放這裡，放在 `slam/core/`（前後端共用的程式碼，而不只是格式）。

## 資料流（ADR 0004）

```
            ┌──────────── 機載 Orin Nano（onboard）────────────┐
 雙目+IMU ─▶│ slam/frontend ──位姿(每幀)──▶ onboard/mavlink ──▶│─▶ PX4
            │      │  ▲                                         │
            └──────┼──┼─────────────────────────────────────────┘
          關鍵幀   │  │ 關鍵幀修正（秒級，可能延遲/中斷）
                   ▼  │
            筆電 RTX 5070（backend）：slam/backend 迴圈閉合、全域最佳化
                   │
                   │ 地圖／最佳化位姿
                   ▼
            桌機 RTX 5070 Ti（vlm）：語意理解 ──語意目標──▶ 機載
```

失效模式與降級行為見 ADR 0004；必須實作在程式中，不只寫在文件。
