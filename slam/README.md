# slam/ — 跨兩台機器的 SLAM

SLAM 是**一個功能、兩個部署位置**，所以放在同一個目錄、按職責分層，而不是拆進 `onboard/` 與筆電目錄：

| 子目錄 | 部署在 | 職責 | 時間限制 |
|---|---|---|---|
| `core/` | 兩邊都用 | 關鍵幀、地圖點、因子的資料結構與序列化；座標轉換 | — |
| `frontend/` | **機載 Orin Nano** | 追蹤、局部建圖／VIO，即時輸出位姿給 PX4 | 硬即時：每幀都要準時 |
| `backend/` | **筆電 RTX 5070** | 迴圈偵測、全域 BA／位姿圖最佳化、地圖合併 | 軟即時：秒級可接受 |
| `eval/` | 任一台（離線） | 用資料集或 rosbag 計算 ATE/RPE，比較設定 | 離線 |

為什麼 `core/` 必須共用：前端送出、後端接收的是**同一種資料結構**。若兩邊各寫一份，版本一錯開，後端就會讀錯前端的關鍵幀，而且這種錯誤通常不會報錯，只會讓地圖慢慢變形。

## 設計原則（詳見 ADR 0004）

1. **機載獨立可飛**：筆電失聯時，前端仍持續輸出位姿（會漂移，但不中斷）。飛控安全絕不依賴網路。
2. **只傳關鍵幀**：不傳原始雙目串流，只傳關鍵幀的特徵／壓縮影像與相對位姿。
3. **修正要平滑套用**：後端回傳的是「過去」關鍵幀的修正，前端以錨點轉換套用到當前位姿；跳變要通知 PX4（ODOMETRY 的 reset counter），不能直接把跳變餵給 EKF。
4. **第三方 SLAM 以 fork + 固定 commit 引入**，所有修改在 fork 上，論文才能清楚說明改了什麼。
